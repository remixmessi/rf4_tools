# RF4 Tools

面向 `rf4_server_simulator` 本地／局域网游戏环境的工具整合包项目，计划统一提供装备参数编辑、装备定制、模型皮肤管理、每杆上鱼信息，以及 Windows 客户端的移速和灯光设置。

**核心原则：服务端与游戏客户端可以在不同电脑上运行，工具必须明确区分操作目标。** 服务端管理使用 Web；客户端工具计划提供本地 Web 和 Windows 应用两种入口。

> **当前处于分析与 UI 设计阶段，尚不是可直接修改游戏的工具。**
>
> 仓库目前仅包含项目分析、技术规划、UI 定稿文档和单文件设计原型。没有正式前端工程、服务端 API 接入、Windows 本地助手或桌面安装包。原型中的保存、连接和回滚均为页面内模拟，不会修改游戏。

## 项目定位

RF4 Tools 是配套工具项目，不是游戏服务端本身，也不包含游戏客户端、模型或贴图资源。

希望解决的问题：

- 将分散的装备与客户端配置操作集中到清晰的工具界面。
- 支持服务端部署在 Windows、Linux、macOS 或 Docker，而游戏客户端运行在另一台 Windows 电脑上的场景。
- 每次操作明确展示目标设备、所属端、连接状态和作用范围。
- 编辑后直接保存，自动记录修改前后值，并为支持恢复的操作提供回滚入口。

本项目面向本地／局域网模拟器环境的研究与工具开发，不承诺适用于官方在线服务。

## 计划功能

下表是开发目标，**不是已实现功能清单**。实际字段、能力和实现方式需要结合 Windows 客户端分析确认。

| 功能 | 计划内容 | 操作归属与限制 |
| --- | --- | --- |
| 装备参数编辑 | 修改鱼竿、渔轮、鱼线等装备参数 | 按字段区分服务端、客户端或双端；不能假定改服务端就会改变客户端表现 |
| 模型与皮肤管理 | 选择和替换装备外观 | 主要依赖 Windows 客户端资源与加载机制分析 |
| 定制装备 | 基于现有装备配置参数、外观和预设 | 服务端生成／发放与客户端外观分别处理 |
| 上鱼面板 | 按鱼竿展示咬口、中钩、搏鱼和鱼信息 | 优先使用服务端每杆状态；不是扫描地图全部鱼的雷达 |
| 人物移速 | 编辑客户端移动相关参数 | 具体字段、生效方式和限制待验证 |
| 灯光设置 | 编辑灯光范围、亮度、角度等 | 具体灯具与可编辑属性待验证 |
| 修改记录与回滚 | 查看修改时间、目标和前后值，恢复可逆修改 | 不保证所有操作都可回滚，真实备份与冲突检测尚未实现 |

## 服务端与客户端分工

### 服务端工作空间：Web

用于管理本地或远程模拟器服务端，计划包含：

- 服务端装备参数。
- 装备定制与发放。
- 每杆上鱼信息。
- 服务端连接、权限和修改记录。

服务端管理不应依赖 Windows 客户端助手在线。

### 客户端工作空间：本地 Web 或 Windows 应用

用于操作游戏所在的 Windows 电脑，计划包含：

- 模型、皮肤和本地资源。
- 客户端控制的装备参数。
- 人物移速和灯光。
- 本地路径、备份与修改记录。

**客户端 Web 需要本机助手提供能力。** 普通网页不能直接修改游戏文件或运行状态；打开远端服务端的管理网页，也不意味着获得本机游戏的控制权限。桌面应用可通过本地模块提供同类能力，具体结构待客户端分析后确定。

```text
电脑 A：Windows / Linux / macOS / Docker
└─ rf4_server_simulator
   └─ 服务端 Web 管理入口 ← 浏览器访问

电脑 B：Windows
├─ 游戏客户端 ─────────→ 电脑 A 的游戏服务端
└─ 客户端本地工具（规划）
   ├─ 本地执行模块／助手
   ├─ 客户端本地 Web
   └─ Windows 桌面应用
```

两端连接、权限、执行结果和故障分别处理。涉及双端的配置不承诺同时成功，也不承诺跨端自动回滚。

## 当前 UI 设计

采用**双工作空间**作为主结构：顶部选择服务端或客户端，侧栏只展示当前空间的功能，内容区始终显示目标设备。

### 编辑与记录

```text
编辑参数 → 校验 → 直接保存 → 自动生成修改记录
                                  ↓
                         按需查看前后值／回滚
```

- 修改前不设置人工审批、强制审阅或勾选确认流程。
- 保存后可查看修改清单，而不是必须先经过清单才能保存。
- “放弃未保存编辑”与“回滚已保存修改”明确区分。
- 原型支持单项与整次回滚展示；存在后续修改或未保存编辑时，不直接覆盖。
- 正式实现仍需区分命令已受理与实际执行完成。

### 配色

默认使用亮色，可切换三套配色：

- **海蓝**：冷白与浅灰背景，蓝色强调。
- **森林绿**：淡绿中性色，深绿强调。
- **暖砂**：米白与暖灰背景，棕金强调。

主题切换不改变目标设备、连接状态或编辑内容。

## 查看设计原型

### 1. 获取仓库

```bash
git clone https://github.com/remixmessi/rf4_tools.git
cd rf4_tools
```

也可以从 GitHub 下载 ZIP 后解压。

### 2. 打开页面

在现代浏览器中直接打开：

```text
doc/design/index.html
```

无需安装 Node.js、Go 或前端依赖。GitHub 文件页面展示的是 HTML 源码，需要下载到本地后打开；仓库目前不提供已部署的在线演示地址。

### 3. 体验交互

1. 在服务端空间修改示例参数，点击“保存修改（演示）”。
2. 打开“修改清单”，查看修改前后值，尝试单项或整次回滚。
3. 切换客户端空间，查看本地能力未就绪时的限制。
4. 开启“模拟本地能力就绪”，体验客户端保存与回滚。
5. 在顶部切换亮色配色。

**所有设备名、地址、参数和连接状态都是示例。** 编辑值、主题选择和修改记录仅存在当前页面内存，刷新即重置。部分功能页面仅展示设计占位，不代表业务已实现。

## 技术方向

当前原型使用独立 HTML、CSS 和 JavaScript，无构建依赖。

正式开发的建议方向如下，尚未全部确定或实施：

| 部分 | 建议方向 |
| --- | --- |
| 共用前端 | React + TypeScript + Vite |
| 数据与业务隔离 | 类型化接口、模拟数据适配器、服务端与本地适配器 |
| 服务端扩展 | 复用并扩展现有 Go 管理接口与游戏状态通道 |
| Windows 桌面宿主 | 优先评估 Tauri 2，Electron 为备选 |
| 客户端助手／扩展 | 根据 Windows 分析结果确定技术与通信方式 |

这些是规划，不是当前仓库的安装或启动要求。UI 交互以定稿文档为准，技术规划中的工程结构供后续实施参考。
